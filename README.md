# Aligner

**팀이 정한 일을, 담당자가 주도권을 유지한 채 투명하게 이어 가도록 돕는 Codex-first 공유 장부**입니다.

Aligner는 팀원의 Codex 대화를 감시하거나, 팀장을 팀원의 작업 승인 게이트로 만드는 제품이 아닙니다. 회의·카톡 등에서 이미 합의한 일을 팀원이 자신의 Codex로 Task 초안으로 정리하고, 웹에서 직접 확인한 뒤 팀에 공유합니다. 중요한 아이디어, 검토, 결정, 이관, 완료 기록은 Task 안에 짧게 남습니다.

## 제품 원칙

- 담당 팀원이 각 Task의 기본 주도권을 가진다.
- AI는 초안을 정리하고 신호를 구조화할 뿐, 진행 승인·방향 결정·책임을 대신하지 않는다.
- 팀장의 결정은 팀원 Codex에 자동으로 주입되지 않는다.
- 팀장은 팀원의 PC, 파일, Codex/Claude 세션, 터미널을 원격으로 읽거나 조작하지 않는다.
- 원문 프롬프트, 전체 transcript, 소스코드, 터미널 출력, API key, 개인 메모는 전송·저장하지 않는다.
- 외부 알림, 커밋 추적, 생산성 분석, 자동 Task 계획은 v0에 넣지 않는다.

## 핵심 개념

| 개념 | 역할 |
| --- | --- |
| `Task` | 담당자가 실제로 실행하는 한 덩어리의 일 |
| Task 기록 | 아이디어, 검토, 결정, 이관, 진행, 완료의 짧은 판단 타임라인 |
| `Draft` | Codex가 만든 웹 확인 전 초안. 팀에 공유되지 않음 |
| 개인 보드 숫자 | 나에게 새로 필요한 행동·확인 항목 수 |

Task는 제목·목표·맥락·완료 기준을 가진 실행 단위입니다. 별도 프로젝트 관리, 채팅, 커밋 로그, 자동 업무 분해 기능은 만들지 않습니다.

## Task 생성 흐름

```text
팀 회의 / 카톡으로 할 일 합의
→ 담당자가 내용을 자기 Codex에 입력
→ “Aligner Task 초안 만들어줘”
→ Codex가 짧은 초안 작성
→ 웹 생성 화면에서 담당자가 확인·수정
→ [생성] 후에만 팀 보드에 등록
```

생성 화면의 필수 항목은 다음 네 가지입니다.

- 제목
- 한 줄 목표
- 왜 하는 일인가
- 완료 기준 한 줄

Codex는 팀원의 일을 멋대로 쪼개거나 후속 Task를 자동 생성하지 않습니다. 팀원이 필요할 때만 `현재 맥락 업데이트`, `검토 요청`, `결정 요청`, `이관 요청`의 초안을 만듭니다.

## 두 개의 웹 화면

### 주도권 보드

팀 전원이 같은 화면을 봅니다.

- 사람별 열에 현재 활성 Task를 표시합니다.
- Task는 현재 담당자 열에 위치합니다.
- 빨강 `결정 필요해요`도 원래 Task 담당자 열에 남습니다.
- 카드에는 제목, 목표, 현재 대표 상태, `진행 중`, 현재 맥락 한 줄을 간략히 표시합니다.
- 팀원 모두 카드 상세를 읽을 수 있지만, 수정·완료 권한은 Task 담당자에게만 있습니다.
- 일반 진행 업데이트는 담당자가 명시적으로 요청할 때만 기록됩니다. 세션·시간·커밋을 감시하지 않습니다.

### 개인 보드

웹을 열었을 때만, 각 사람에게 필요한 항목을 숫자로 보여줍니다. 이메일·Slack·웹 푸시·Codex 강제 알림은 사용하지 않습니다.

팀장의 개인 보드는 다음 순서를 고정합니다.

1. 결정
2. 실행
3. 검토
4. 팀 이관 요청
5. 팀 로드맵

팀원은 자신의 실행, 자신에게 온 검토 요청, 이관 요청, 자신의 Task에 새로 기록된 결정·검토 결과를 봅니다. 직접 관련 없는 팀 변화에는 숫자가 붙지 않습니다.

## 상태와 판단 기록

카드에는 현재 대표 상태 하나만 표시하고, 전체 이력은 카드 상세에 쌓습니다.

| 상태 | 표현 | 의미 |
| --- | --- | --- |
| 초록 | `아이디어 있어요` | 미래의 갈림길이나 확장 가능성을 공유. 담당자 주도권 유지 |
| 노랑 | `검토해주세요` | 검토를 요청. 담당자 주도권 유지 |
| 빨강 | `결정 필요해요` | 실제 갈림길의 판단을 결정권자에게 요청 |
| 회색 | `진행 중` 또는 결과 정리 | 일반 진행, 또는 결정 기록 후의 진행 |

예를 들어 Task가 노랑으로 시작한 뒤 초록 아이디어 공유, 빨강 결정 요청을 거칠 수 있습니다. 결정이 기록되면 자동으로 노랑이나 초록으로 되돌아가지 않고 회색이 됩니다. 새 검토나 새 아이디어가 필요할 때만 담당자가 새 기록을 만듭니다.

## 카드 상세

카드를 누르면 다음만 확인할 수 있습니다.

- 왜 이 일을 하는지
- 완료 기준
- 현재 진행과 다음 진행
- 아이디어·검토·결정 기록
- 이관 시: 어디까지 했고 무엇을 넘겼는지
- 완료 시: 최종 결과 한 줄과 선택 근거 링크

상세 화면은 작업 일지나 대화 transcript가 아니라, **왜 시작했고 → 어떤 갈림길이 있었고 → 누가 무엇을 결정했고 → 어디까지 진행했는지**를 남기는 구조화된 기록입니다.

## 검토·결정·이관

### 검토

지정된 검토자는 카드 상세에서 한 줄 검토 의견과 선택 근거 링크를 남기고 `검토 완료`를 누릅니다. Task 담당자 개인 보드에 숫자가 붙고, 담당자는 결과를 확인해 반영합니다.

### 결정

팀장은 카드 상세에서 `결정 기록`을 남깁니다. 이 기록은 담당자 개인 보드에 표시되지만, 담당자의 Codex에 자동으로 주입되거나 실행되지는 않습니다. 담당자가 확인한 뒤 계속 진행합니다.

### 이관

Task 이관은 실제 주도권 변경이므로 대상자의 명시적 `수락 / 거절`이 필요합니다.

- 수락: Task가 새 담당자 열로 이동합니다.
- 거절: Task는 원래 담당자 열에 유지되고, 이유를 선택적으로 남깁니다.

이관 요청만으로는 책임자가 바뀌지 않습니다.

## 완료와 로드맵

담당자가 Codex에서 완료 초안을 만들고, 웹에서 최종 결과 한 줄을 확인한 뒤 `완료`를 누릅니다.

- 완료된 Task는 활성 주도권 보드에서는 사라집니다.
- 로드맵과 카드 상세에는 계속 남습니다.
- 근거 링크는 선택입니다.
- 후속 Task는 자동 생성하지 않으며, 팀이 다시 합의한 뒤 별도 Task로 만듭니다.

팀 로드맵은 사람별 행으로 구성되며, 왼쪽에서 오른쪽으로 Task 생성 시간 흐름을 보여줍니다. 완료된 Task도 유지합니다. 이관이 수락되면 이전 담당자 카드에는 점선 테두리가 남고, 새 담당자 행에 이어지는 카드가 생깁니다. 연결선은 그리지 않으며, 카드 상세에서 이관 기록을 확인합니다.

## 전송 확인 경계

| 행동 | 최종 확인 위치 |
| --- | --- |
| Task 생성 | 웹 |
| 결정 요청 | 웹 |
| Task 이관 | 웹 |
| 완료 | 웹 |
| 아이디어 공유 | Codex 안의 담당자 확인 |
| 검토 요청·결과 | Codex 안의 담당자 확인 |
| 진행 업데이트 | Codex 안의 담당자 확인 |

웹에서 확정되기 전의 `Draft`는 팀 보드, 로드맵, 다른 사람의 개인 보드에 나타나지 않습니다.
