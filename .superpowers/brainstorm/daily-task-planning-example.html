수요일 오늘의 할 일 배정 예시

사람당 5시간을 꽉 채우는 대신, 4시간 계획 + 1시간 버퍼로 잡은 예시입니다. 각 task는 Codex 작업, 현실 확인, 협응 부담을 같이 봅니다.

배정 기준: 사람당 계획 작업량 4시간, 버퍼 1시간. 2시간 핵심 task 1개 + 1시간 보조 task 1개 + 30분 확인 task 1-2개를 기본 형태로 잡습니다. 협응도 상 task는 실제 시간보다 무겁게 계산합니다.
조수현 · 계획 4시간 / 버퍼 1시간
오늘 목표: 하드웨어 변경이 전체 구조에 주는 영향을 판단하고, 팀 task 변경 승인 기준을 정리합니다.
1. 하드웨어 변경 시 모델 실행 구조 영향 검토
2시간Codex 적합도 높음협응도 상
현실 확인: 없음
완료 기준: ESP32 변경 시 모델 실행 위치, 데이터 흐름, 영향받는 task를 정리해 Slack에 제출
2. Subjector task 승인 기준 정리
1시간Codex 적합도 중간협응도 상
현실 확인: 팀원 의견 필요 가능
완료 기준: 어떤 변경은 팀장 승인, 어떤 변경은 영향받는 사람 동의가 필요한지 기준 작성
3. OpenAI API billing 확인
30분현실 확인 있음협응도 하
완료 기준: API 결제 설정 가능 여부와 테스트 호출 결과를 Slack에 기록
김조은 · 계획 4시간 / 버퍼 1시간
오늘 목표: ESP32 변경 가능성을 판단할 수 있는 근거를 모으고 추천안을 제출합니다.
1. ESP32와 라즈베리파이 비교 후 추천안 작성
2시간Codex 적합도 높음협응도 상
현실 확인: 일부 필요
완료 기준: 전력, 센서 연결, 구현 난이도, 시연 안정성 기준 추천안 제출
2. 부품 구매 가능 여부와 가격 확인
1시간현실 확인 있음협응도 중
완료 기준: 구매 가능한 후보 2개 이상, 가격, 배송 가능성을 Slack에 제출
3. 센서 연결 방식 후보 메모
30분Codex 적합도 중간협응도 하
완료 기준: GPIO/I2C/UART 중 가능한 연결 후보를 간단히 정리
배민성 · 계획 4시간 / 버퍼 1시간
오늘 목표: 실제 장소에서 네트워크와 데이터 송신 가능성을 확인해 하드웨어 선택 근거를 보완합니다.
1. 502, 503호 Wi-Fi ID와 연결 가능 여부 확인
2시간현실 확인 있음협응도 중
완료 기준: 각 강의실 Wi-Fi ID, 연결 가능 여부, 신호 상태를 Slack에 제출
2. ESP32 기준 데이터 송신 방식 조사
1시간Codex 적합도 높음협응도 상
현실 확인: Wi-Fi 확인 결과와 연결
완료 기준: ESP32에서 가능한 송신 방식과 필요한 조건 정리
3. 테스트 로그 형식 제안
30분Codex 적합도 높음협응도 하
완료 기준: Slack에 붙여넣을 수 있는 테스트 로그 템플릿 작성
Subjector는 task 시간이 4시간을 넘으면 “오늘 안에 과함”으로 표시하고, 협응도 상 task가 많으면 한 사람에게 몰리지 않도록 조정합니다.
