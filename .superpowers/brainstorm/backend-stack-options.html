Subjector 서버 기술 선택

둘 다 가능하지만, Slack 봇 중심인지 AI 파일 처리 중심인지에 따라 자연스러운 선택이 달라집니다.

1번. Node.js + Slack Bolt.js
Slack 봇에 특화버튼/모달 쉬움Render 배포 쉬움
Slack 이벤트 수신파일 업로드, 텍스트 메시지, 버튼 클릭을 Bolt.js가 받습니다.
버튼/모달 처리찬성/반대, 변경 요청, 화자 매핑 모달을 Slack 방식에 맞게 구현하기 쉽습니다.
AI 처리 호출OpenAI API를 호출하고 결과를 Slack에 다시 씁니다.
오디오 분할ffmpeg 같은 도구를 서버에서 실행하거나 라이브러리로 처리합니다.

장점

  • Slack 봇 공식 패턴에 가깝습니다.
  • 버튼/모달/이벤트 처리가 자연스럽습니다.
  • 3일 MVP에 빠릅니다.

주의

  • 오디오 처리 코드는 별도 라이브러리/ffmpeg가 필요합니다.
  • Python보다 데이터 처리 감각은 조금 덜 편할 수 있습니다.
2번. Python + FastAPI
AI/파일 처리 친숙API 서버 깔끔Slack 직접 구현 증가
Slack 이벤트 수신FastAPI endpoint로 직접 받고 검증합니다.
버튼/모달 처리Slack payload, ack, modal 응답을 직접 더 많이 다룹니다.
AI 처리 호출OpenAI, 오디오 분할, 텍스트 처리 코드는 Python으로 편합니다.
배포Render에 Python web service로 배포합니다.

장점

  • 오디오/텍스트 처리에 익숙한 생태계가 많습니다.
  • AI 파이프라인을 쓰기 편합니다.

주의

  • Slack 버튼/모달 구현을 더 직접 챙겨야 합니다.
  • MVP 핵심이 Slack UX라면 시간이 더 걸릴 수 있습니다.
추천: Subjector MVP는 Slack 버튼, 모달, 스레드, DM이 핵심이므로 Node.js + Slack Bolt.js가 더 잘 맞습니다. 오디오 분할은 ffmpeg를 붙여 해결하고, AI 처리는 OpenAI API 호출로 처리합니다.
