# IDEA CRUISE MVP 사용 설명서

이 문서는 현재 Slack에서 수동 테스트를 완료한 실행 흐름과 2026-06-30에 정리한 새 제품 방향을 함께 기록한다.

MVP 제품 이름은 `IDEA CRUISE`다. 현재 Slack 봇과 서버 구현은 아직 `Subjector` 이름을 사용하지만, 제품 안에서 Subjector는 작업 전달, 진행, 인수인계 정리를 담당하는 실행 계층으로 본다.

## IDEA CRUISE가 하는 일

IDEA CRUISE는 회의에서 나온 아이디어가 실제 task가 되기 전에 목표, 기준, 산출물 수준, 인수인계 기준을 정렬하도록 돕는다. 그 뒤 Subjector 실행 계층이 task 전달, 진행, 결과 정리, 프로젝트 누적 기록을 Slack에서 처리한다.

팀원은 Codex, 구글링, 자료조사, 직접 개발 등 자신에게 맞는 방식으로 작업할 수 있다. IDEA CRUISE는 특정 도구 사용을 강제하지 않고, 각자의 작업물이 다음 사람에게 잘 이어지도록 기준과 맥락을 정리한다.

## 사용하는 Slack 위치

- IDEA CRUISE 로컬 웹앱: `https://subjector.onrender.com/idea-cruise`에서 회의 중 기준 정렬, 충돌/대안/범위 감지, task 기준 패킷 작성
- `#회의-결과록`: IDEA CRUISE 회의 결과록, 회의 녹음 전사, 이후 IDEA CRUISE가 참고할 회의 맥락
- `#in-process`: 개인별 task 보드와 task 상세 스레드
- `#finals`: 프로젝트 누적 결과 정리
- Subjector Bot DM: 출근, 최신화, 퇴근, 회의 의견 입력, finals 업데이트

## 회의 전 기준 정렬

회의를 시작하거나 회의 중 task가 구체화될 때 `https://subjector.onrender.com/idea-cruise`를 연다.

이 화면은 Slack 봇처럼 명령을 처리하는 곳이 아니라, 회의 내용을 보면서 task의 기준을 정리하는 로컬 웹 작업대다. 입력 내용은 브라우저에 임시 저장되므로 새로고침해도 같은 브라우저에서는 draft가 남는다.

IDEA CRUISE 화면에서 먼저 정리할 것은 아래 항목이다.

- 이 task의 진짜 목적
- 빠른 검증용, 내부 사용 가능한 초안, 완성도 있는 최종 산출물 중 어디에 가까운지
- 성공 기준
- 반드시 해야 하는 것
- 생략해도 되는 것
- 담당자가 재량으로 판단해도 되는 것
- 다음 사람에게 넘겨야 할 정보
- 기준이 아직 애매한 부분
- 팀장에게 다시 확인해야 할 질문

정리가 끝나면 `기준 정렬 패킷 복사`를 눌러 회의 기록, task 후보 수정, Codex 프롬프트, 또는 팀원에게 전달할 작업 설명에 붙여넣는다.

IDEA CRUISE는 점수나 `상/중/하`로 task를 설명하지 않는다. 대신 무엇이 충분히 정리되었고, 무엇이 아직 흐리며, 다음 사람이 이어받기 전에 어떤 질문을 확인해야 하는지 문장으로 풀어준다.

## 하루 작업 흐름

1. Subjector Bot DM에 `출근`을 보낸다.
2. `#in-process`에서 내 task 보드를 확인한다.
3. Codex로 진행할 task는 `수락 및 Codex 프롬프트 생성`을 누른다.
4. 직접 조사, Word 정리, 그림 제작, 실험 등으로 진행할 task는 `수락하고 직접 진행`을 누른다.
5. Codex를 쓰는 경우 스레드에 생성된 프롬프트를 복사해서 Codex에 붙여넣는다.
6. 작업이 끝나면 `완료`를 누르고 결과 요약을 제출한다.
7. 오늘 끝내지 못하면 `오늘은 여기까지`를 누르고 진행 상태를 제출한다.
8. Word, PDF, 이미지, 정리 파일을 같이 제출해야 하면 `파일 첨부 제출`을 누르고 제출 종류를 고른다.
9. 퇴근 전 Subjector Bot DM에 `퇴근`을 보낸다.

## #in-process task 상태

- `미시작`: 아직 수락하지 않은 task
- `수락`: Codex 프롬프트를 생성했거나 직접 진행으로 수락한 task
- `이어받기 전 확인 필요`: 다음 사람이 이어받기 전에 기준, 근거, 리스크, 산출물 설명을 더 정리해야 하는 task
- `오늘은 여기까지`: 오늘은 더 진행하지 않고 다음 작업으로 넘기는 task
- `변경 요청 중`: 작업 중 다른 사람에게 영향을 줄 수 있는 변경을 요청한 task
- `완료`: task가 끝난 상태

완료된 task는 긴 목록을 줄이기 위해 `#in-process` 보드에서는 사라진다. 대신 해당 보드 스레드에 `[task 완료 기록]` 댓글이 남고, DB와 `퇴근` 요약, `#finals` 누적 정리에는 계속 반영된다.

## Codex 작업 규칙

`수락 및 Codex 프롬프트 생성`을 누르면 Subjector가 task 맥락을 포함한 긴 프롬프트를 만든다.

Codex를 쓰지 않는 task는 `수락하고 직접 진행`을 누른다. 이 경우 Subjector는 Codex 프롬프트를 만들지 않고 task 상태만 `수락`으로 바꾼다.

Codex 작업 중 다음 상황이면 그냥 진행하지 말고 `변경 요청`을 사용한다.

- 내 판단으로 task 방향을 바꿔야 할 것 같다.
- 다른 사람의 task나 일정에 영향을 준다.
- 회의에서 정한 내용과 충돌할 수 있다.
- “이건 말하고 진행했어야 했다”는 상황이 생길 수 있다.

`변경 요청`에는 Codex가 작성한 초안을 붙여넣는다. 초안에는 최소한 `[변경 제안]`, `[주장]`, `[근거]`가 들어가야 한다.

## 완료와 인수인계 점검

`완료` 제출은 사람을 채점하기 위한 절차가 아니다. IDEA CRUISE는 제출된 결과가 다음 사람에게 얼마나 잘 이어질 수 있는지 인수인계 관점으로 점검한다.

- 다음 사람이 바로 이어받을 수 있으면 task가 `완료`가 된다.
- 기준, 근거, 리스크, 다음 행동이 부족하면 task가 `이어받기 전 확인 필요`가 되고, 스레드에 맥락 중심 피드백이 남는다.
- 이 상태에서는 사용자가 결과를 다시 정리해 인수인계 내용을 보강한다.
- 피드백은 `상/중/하`나 숫자 점수로 설명하지 않는다. 무엇이 좋고, 어느 점이 부족하고, 무엇을 보강하면 다음 사람이 더 쉽게 이어받을 수 있는지 자연어로 설명한다.

`완료`와 `오늘은 여기까지`는 Codex 결과뿐 아니라 직접 작업 결과도 제출할 수 있다.

- 파일 없이 제출할 때는 `완료` 또는 `오늘은 여기까지`를 누른다.
- Word, PDF, 이미지, 표, 조사 자료 같은 파일을 같이 제출할 때는 `파일 첨부 제출`을 누른다.
- `파일 첨부 제출`에서는 `완료` 또는 `오늘은 여기까지` 중 제출 종류를 먼저 고른다.
- 파일을 첨부했다면 `첨부 파일 설명`에 무엇을 보면 되는지 적는다.
- 인수인계 점검은 제출 요약, 첨부 파일 설명, 파일명을 함께 보고 다음 사람이 이어받을 수 있는 맥락으로 바꾼다.

## 회의 녹음으로 맥락 보강하기

1. `#회의-결과록`에 회의 녹음 파일을 업로드한다.
2. Subjector가 업로드를 기록하고 전사를 시작한다.
3. 전사가 완료되면 스레드에 전사 요약이 남고, 자동 task 생성은 진행하지 않는다.
4. 저장된 전사 맥락은 IDEA CRUISE 카드 생성 시 최근 회의 맥락으로 함께 전달된다.
5. 실제 task 생성은 IDEA CRUISE에서 완료된 topic page를 기준으로만 진행한다.

## 녹음 없이 회의 기록 남기기

짧은 회의 결과나 결정 사항은 녹음 없이 Subjector Bot DM에 직접 입력할 수 있다.

```text
회의 기록: ESP32 기준으로 진행하고 라즈베리파이는 제외하기로 함
```

이 명령을 보내면 녹음 전사 없이도 회의 맥락이 저장된다. 저장된 맥락은 IDEA CRUISE 카드 생성 시 참고 자료로 사용되며, 자동 task 생성은 진행하지 않는다.

## 퇴근 요약

퇴근 전 Subjector Bot DM에 아래처럼 보낸다.

```text
퇴근
```

Subjector는 그날의 완료, 오늘은 여기까지, 변경 요청, 미정리 task를 한 번만 요약해서 DM으로 보낸다.

## #finals 누적 정리

`#finals`는 오늘 할 일 목록이 아니라 프로젝트 전체 누적 결과 정리다.

Subjector는 누적 task, 완료/중단 제출 결과, 변경 요청 이력을 LLM에 넘겨 자연어 요약을 만든다. 요약은 다음 구조로 작성된다.

- `프로젝트 현재 상태`: 오늘 회의/작업 이후 프로젝트가 어디까지 왔고 무엇이 중요해졌는지
- `충돌/변경 이력`: task 변경, 기준 변경, 기존 방향과 충돌할 수 있는 내용
- `다음 회의/내일 볼 것`: 다음에 결정하거나 확인해야 할 것

`#finals` 업데이트 시점은 두 가지다.

- 세 명이 모두 Subjector Bot DM에 `퇴근`을 보내면 즉시 `#finals`를 업데이트한다.
- 누군가 `퇴근`을 보내지 않았더라도 18:00 KST 이후에는 그날 `#finals`를 1회 자동 업데이트한다.

수현님은 필요할 때 Subjector Bot DM에 아래처럼 보내 즉시 업데이트할 수 있다.

```text
finals 업데이트
```

Subjector가 최신 누적 정보를 다시 요약해 `#finals`에 바로 반영한다. 최종 요약은 최신 상태로 다시 작성되지만, 변경/충돌 이력은 남긴다. LLM 요약에 실패하면 기존 task/result 기록을 바탕으로 기본 자연어 요약을 만들어 `#finals`를 업데이트한다.

## 자주 쓰는 DM 명령

```text
출근
```

오늘 업무 시작을 기록하고 `#in-process` 보드를 만들거나 갱신한다.

```text
최신화
```

출근 기록은 건드리지 않고 `#in-process` 보드만 갱신한다.

```text
퇴근
```

오늘 한 일 요약을 DM으로 받는다.

```text
회의 기록: 내용
```

녹음 없이 회의 기록을 IDEA CRUISE 참고 맥락으로 저장한다.

```text
finals 업데이트
```

수현님 전용 명령이다. `#finals` 누적 정리를 즉시 업데이트한다.

```text
테스트 task 정리
```

수현님 전용 테스트 정리 명령이다. 제목에 `테스트`가 들어간 미완료 task를 보관 처리하고 `#in-process`를 갱신한다.

## 테스트용 강제 진행

테스트 중 다른 팀원의 답변을 받을 수 없을 때만 사용한다.

Render 환경변수에 아래 값을 넣고 배포하면 켜진다.

```env
ENABLE_TEST_PARTICIPANT_SKIP=true
```

아직 답변 대기자가 있을 때 수현님 DM에 `테스트용: 현재 답변만으로 진행` 버튼이 뜬다. 실제 운영에서는 모든 참여자의 답변을 받은 뒤 진행하는 것을 권장한다.

## 서버와 배포

- 서버는 Render에서 실행된다.
- GitHub `main`에 push하면 Render가 자동 배포한다.
- Slack에서 바뀐 기능이 안 보이면 Render에서 `Deploy latest commit`을 누른다.
- 상태 확인은 `https://subjector.onrender.com/health`에서 PIN 입력 후 확인한다.

## MVP 테스트 완료 항목

- 회의 녹음 업로드
- 전사 완료와 IDEA CRUISE 참고 맥락 저장
- IDEA CRUISE에서 회의 맥락을 참고한 카드 생성
- `#in-process` task 반영
- 수락 및 Codex 프롬프트 생성
- 인수인계 점검과 이어받기 전 확인 필요 처리
- 완료 task 숨김과 완료 기록 스레드 남김
- 테스트 task 정리
- 녹음 없는 `회의 기록: 내용` 맥락 저장 흐름
- 퇴근 요약
- `#finals` 누적 정리 반영
