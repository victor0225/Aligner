# Subjector MVP 사용 설명서

이 문서는 현재 Slack에서 수동 테스트를 완료한 Subjector MVP 기준이다.

## Subjector가 하는 일

Subjector는 회의 내용을 task로 만들고, 각자 Codex에서 일할 수 있도록 프롬프트를 준비하며, 하루 작업 결과와 프로젝트 누적 결과를 Slack에 정리하는 봇이다.

팀원은 Slack에서 task를 확인하고, Codex에서 작업한 뒤, 결과를 다시 Slack에 제출한다.

## 사용하는 Slack 위치

- `#회의-결과록`: 회의 녹음 업로드, 회의 전사, Speaker A/B/C 매핑, 회의 기반 task 생성
- `#in-process`: 개인별 task 보드와 task 상세 스레드
- `#finals`: 프로젝트 누적 결과 정리
- Subjector Bot DM: 출근, 최신화, 퇴근, 회의 의견 입력, finals 업데이트

## 하루 작업 흐름

1. Subjector Bot DM에 `출근`을 보낸다.
2. `#in-process`에서 내 task 보드를 확인한다.
3. 시작할 task에서 `수락 및 Codex 프롬프트 생성`을 누른다.
4. 스레드에 생성된 Codex 프롬프트를 복사해서 Codex에 붙여넣는다.
5. Codex와 작업한다.
6. 작업이 끝나면 `완료`를 누르고 Codex가 낸 완료 결과를 붙여넣는다.
7. 오늘 끝내지 못하면 `오늘은 여기까지`를 누르고 Codex가 낸 진행 상태를 붙여넣는다.
8. 퇴근 전 Subjector Bot DM에 `퇴근`을 보낸다.

## #in-process task 상태

- `미시작`: 아직 수락하지 않은 task
- `수락`: Codex 프롬프트를 생성했고 작업 중인 task
- `보완 필요`: 완료 제출이 부족해서 다시 보완해야 하는 task
- `오늘은 여기까지`: 오늘은 더 진행하지 않고 다음 작업으로 넘기는 task
- `변경 요청 중`: 작업 중 다른 사람에게 영향을 줄 수 있는 변경을 요청한 task
- `완료`: task가 끝난 상태

완료된 task는 긴 목록을 줄이기 위해 `#in-process` 보드에서는 사라진다. 대신 해당 보드 스레드에 `[task 완료 기록]` 댓글이 남고, DB와 `퇴근` 요약, `#finals` 누적 정리에는 계속 반영된다.

## Codex 작업 규칙

`수락 및 Codex 프롬프트 생성`을 누르면 Subjector가 task 맥락을 포함한 긴 프롬프트를 만든다.

Codex 작업 중 다음 상황이면 그냥 진행하지 말고 `변경 요청`을 사용한다.

- 내 판단으로 task 방향을 바꿔야 할 것 같다.
- 다른 사람의 task나 일정에 영향을 준다.
- 회의에서 정한 내용과 충돌할 수 있다.
- “이건 말하고 진행했어야 했다”는 상황이 생길 수 있다.

`변경 요청`에는 Codex가 작성한 초안을 붙여넣는다. 초안에는 최소한 `[변경 제안]`, `[주장]`, `[근거]`가 들어가야 한다.

## 완료와 보완 제출

`완료` 제출은 LLM이 수행 적절성을 검수한다.

- 충분하면 task가 `완료`가 된다.
- 부족하면 task가 `보완 필요`가 되고, 피드백이 스레드에 남는다.
- `보완 필요` 상태에서는 버튼 이름이 `보완 제출`로 바뀐다.
- 보완 내용을 다시 제출하면 LLM이 다시 검수하고 점수를 갱신한다.

## 회의 녹음에서 task 만들기

1. `#회의-결과록`에 회의 녹음 파일을 업로드한다.
2. Subjector가 업로드를 기록하고 전사를 시작한다.
3. 전사가 완료되면 스레드에 Speaker A/B/C 매핑 버튼이 뜬다.
4. 수현님이 Speaker A/B/C를 실제 팀원으로 지정한다.
5. 회의에 참여한 팀원에게 DM으로 “이번 회의에서 먼저 해야 한다고 보는 일” 입력 요청이 간다.
6. 각 팀원은 DM 버튼을 눌러 의견을 적는다.
7. 모든 답변이 모이면 Subjector가 회의 전사와 팀원 의견을 함께 보고 task 후보를 만든다.
8. 각 담당자는 자기 DM에서 후보를 `채택`, `제외`, `수정` 중 하나로 처리한다.
9. `채택` 또는 `수정해서 반영`된 후보만 실제 task로 저장된다.
10. Subjector Bot DM에 `최신화`를 보내면 `#in-process`에 새 task가 반영된다.

## 녹음 없이 회의 기록 남기기

짧은 회의 결과나 결정 사항은 녹음 없이 Subjector Bot DM에 직접 입력할 수 있다.

```text
회의 기록: ESP32 기준으로 진행하고 라즈베리파이는 제외하기로 함
```

이 명령을 보내면 녹음 전사 없이도 회의 task 생성 흐름이 시작된다. 이후 팀원 의견 입력, task 후보 생성, 채택/제외/수정 흐름은 녹음 회의와 같다.

## 퇴근 요약

퇴근 전 Subjector Bot DM에 아래처럼 보낸다.

```text
퇴근
```

Subjector는 그날의 완료, 오늘은 여기까지, 변경 요청, 미정리 task를 한 번만 요약해서 DM으로 보낸다.

## #finals 누적 정리

`#finals`는 오늘 할 일 목록이 아니라 프로젝트 전체 누적 결과 정리다.

수현님은 Subjector Bot DM에 아래처럼 보낼 수 있다.

```text
finals 업데이트
```

Subjector가 미리보기를 만들고, 수현님이 `승인하고 반영하기`를 누르면 `#finals`가 업데이트된다. 최종 요약은 최신 상태로 다시 작성되지만, 변경/충돌 이력은 남긴다.

## 자주 쓰는 DM 명령

```text
출근
```

오늘 업무 시작을 기록하고 `#in-process` 보드를 만들거나 갱신한다.

```text
최신화
```

출근 기록은 건드리지 않고 `#in-process` 보드만 갱신한다.

```text
퇴근
```

오늘 한 일 요약을 DM으로 받는다.

```text
회의 기록: 내용
```

녹음 없이 회의 기록을 저장하고 task 후보 흐름을 시작한다.

```text
finals 업데이트
```

수현님 전용 명령이다. `#finals` 누적 정리 미리보기를 만든다.

```text
테스트 task 정리
```

수현님 전용 테스트 정리 명령이다. 제목에 `테스트`가 들어간 미완료 task를 보관 처리하고 `#in-process`를 갱신한다.

## 테스트용 강제 진행

테스트 중 다른 팀원의 답변을 받을 수 없을 때만 사용한다.

Render 환경변수에 아래 값을 넣고 배포하면 켜진다.

```env
ENABLE_TEST_PARTICIPANT_SKIP=true
```

아직 답변 대기자가 있을 때 수현님 DM에 `테스트용: 현재 답변만으로 진행` 버튼이 뜬다. 실제 운영에서는 모든 참여자의 답변을 받은 뒤 진행하는 것을 권장한다.

## 서버와 배포

- 서버는 Render에서 실행된다.
- GitHub `main`에 push하면 Render가 자동 배포한다.
- Slack에서 바뀐 기능이 안 보이면 Render에서 `Deploy latest commit`을 누른다.
- 상태 확인은 `https://subjector.onrender.com/health`에서 PIN 입력 후 확인한다.

## MVP 테스트 완료 항목

- 회의 녹음 업로드
- 전사 완료와 Speaker A/B/C 매핑
- 회의 후 개인 의견 입력
- 현재 답변만으로 task 후보 생성
- task 후보 채택/제외/수정
- `#in-process` task 반영
- 수락 및 Codex 프롬프트 생성
- 완료 검수와 보완 제출
- 완료 task 숨김과 완료 기록 스레드 남김
- 테스트 task 정리
- 녹음 없는 `회의 기록: 내용` 흐름
- 퇴근 요약
- `#finals` 누적 정리 반영
